      SYSTEM DESIGN / 01

      From overdue invoice to a reviewable decision.

      A collections call is useful only if it produces a trustworthy next action. This system decides whom to call, conducts one focused conversation, then turns the transcript into structured evidence.

      1invoice per call
      3 minhard call limit
      5post-call specialists
      1supervised write decision
      01 / ARCHITECTURE

      One continuous data path

      The same post-call pipeline handles live calls and saved replays.

      01Account dataAR sheet · invoices · contact history
      02Pre-call gateSuppress ineligible accounts · score priority · build context
      03Voice agentFixed disclosure · authority check · one invoice
      04Post-call reviewFive parallel extractors · supervisor merge
      05Next actionAuto-write or human exception queue

      The write-back path reconciles rows by call_id, so retrying an analysis does not duplicate records. The public demo previews the row shape; it does not write to a customer Sheet. The first nine-call eval found two false writes, so this path still needs human oversight before real-customer use.

      02 / EXECUTION

      Where each decision lives

      Code handles fixed rules. Models handle conversation and transcript interpretation. The supervisor routes low-confidence and rule-breaking calls to humans.

      ⌁BEFORE THE CALL

      Eligibility before outreach

      Code suppresses paid accounts, open disputes, active promises, opt-outs, wrong contacts, cooldowns, out-of-hours calls, and 90+ day debt routed to a person. Every suppression has a logged reason.

      Prioritybalance × aging × broken-PTP escalation × contactability

      The context pack carries contact, invoices, total balance, promise history, disputes, last contact, and language.

      ◉DURING THE CALL

      A focused voice conversation

      Vapi starts with a fixed disclosure and authority check before the model speaks. The agent works the most overdue invoice, asks for a concrete payment commitment when possible, and hands off other invoices.

      GuardrailsOne question per turn · supplied invoice facts only · three-minute cap

      Tool results must be checked before the agent says an action was completed.

      ◇AFTER THE CALL

      Extract, validate, route

      Outcome, promise, dispute, compliance, and summary specialists read the transcript in parallel. Code validates dates, amounts, methods, and arithmetic.

      SupervisorLow confidence or a hard compliance violation sends the call to human review.

      A valid result maps to call log, promise, dispute, or exception records.

      03 / TRADE-OFFS

      Design choices worth defending

      01

      One invoice, fully handled

      Early calls tried to cover every invoice and ran out of time. A complete outcome on the oldest debt plus a separate callback is more useful than several partial conversations.

      02

      Arithmetic stays in code

      The model extracts what the caller said. Deterministic checks decide whether a promise is complete, future-dated, within the balance, and supported by a valid method.

      03

      90+ days goes to a human

      This is a product boundary for higher-risk conversations, not a limitation of the voice stack.

      04

      Live demo with a replay fallback

      Server-side spend, daily, and visitor caps protect the finite Vapi balance. When a live call is unavailable, a saved conversation still runs through the actual analysis path.

      01 / INCIDENTS

      Three failures that changed the design

      2026-09-30 · DATA MATCHING

      A spoken hyphen downgraded a valid promise

      OBSERVED

      A complete, in-full promise landed in the exception queue with amount_within_outstanding=false.

      ROOT CAUSE

      The transcript said US-CS/26-27/0002; the account record said USCS/26-27/0002. Exact string matching missed the invoice.

      CHANGE

      Normalize invoice references to uppercase letters and digits before matching.

      Saved-call replay exposed a production-shaped data mismatch that hand-written fixtures had hidden.

      2026-09-17 · PROMPT BEHAVIOR

      Passing tests missed two conversation regressions

      OBSERVED

      The agent bundled amount, date, and method into one turn, then sometimes recorded the full invoice balance without asking what the caller would pay.

      ROOT CAUSE

      More specific branch wording contradicted the one-question rule. Tests checked that phrases existed, not what the branch instructed the agent to do.

      CHANGE

      Make each required ask explicit and sequential, with a regression test for the will-pay branch.

      A prompt is executable behavior; a green test suite does not prove its branches work in conversation.

      2026-09-16 · ARITHMETIC

      The model was asked to verify its own math

      OBSERVED

      A promise of 365,500 against 85,000 + 280,500 was marked over balance. A separate misstated total passed compliance with a perfect score.

      ROOT CAUSE

      Both specialists relied on language-model arithmetic where an exact comparison was required.

      CHANGE

      Keep extraction in the model; validate balance, dates, methods, and stated totals in code.

      Use the model to read unstructured speech, then let code decide deterministic facts.

      02 / MORE SIGNAL

      Smaller incidents, concrete fixes

      WEBHOOKS

      Dead air was a routing failure

      An expired tool endpoint left the caller in silence. Add a pre-call reachability check and a spoken timeout fallback.

      TOOL USE

      Speech is not execution

      The agent said it logged a dispute without calling the tool. Tighten tool instructions and log raw webhook requests, including no-op requests.

      PRIORITY

      A passing test asserted the wrong rule

      Broken promises lowered priority until real promise history exercised the formula. They now escalate it.

      INTEGRATION

      The fake backend was too forgiving

      It accepted a new Sheet field that the real writer silently dropped. Test the real header mapping.

      PROVIDER DATA

      The summary field never arrived

      Real Vapi payloads showed the built-in summary path was deprecated. A dedicated summary specialist replaced it.

      SCOPE

      Hinglish was cut deliberately

      It failed the same way on two models. The demo now focuses on reliable English rather than a third unverified rewrite.
